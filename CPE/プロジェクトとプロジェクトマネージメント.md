# プロジェクトとプロジェクトマネージメント

## プロジェクトは
- 1つまたは複数の定義された目標を達成するための有期的な取り組み
- 独自のプロダクト、サービス、所産を創造するために実施される有期的な業務

```
プロジェクトーー独自性              定常業務ーー反復性（PDCA)
          ｜ー有機性                     |ー継続性
```
### プロジェクトの成功のために必要なもの <br>
QCDのバランス <br>
Q=価値実現に必要な**品質** <br>
C=生み出す価値に見合った**コスト**、採算性 <br>
D=タイムリーに価値提供するための**納期** <br>

→　いずれかを優先させると他の要素が疎かになる関係 <br>
→　独自性に伴い、内外の変化の影響を受け続ける <br>
⇨　プロジェクトマネジメントでQCDのバランスを取り、価値を最大化する <br>

### 成果物作成プロセス
- 求められた要件・方向に向かって進めず　→　手戻り
- 進捗・品質を定期的/定量的に把握せず  →  遅延
- 要求変更やリスクの発現に対応できず   →  作業肥大

  　　　　  ↑　適切なコストをかけて計画し、コントロールする

プロジェクトマネジメント

　　　　　　　　　　　→　実行  
立ち上げ　→　計画　　　　↓ ↑　　　          → 終結 <br>
　　　　　　　　　　　→  コントロール

**1~2割の時間を割いて、プロジェクトマネジメントにかける**

### 独自性と有期性に伴い発生する問題
- 定義された仕様に、のちのち変更が生じる
- 当初の見積もりを超えた作業が発生する
- 進捗・品質の実態がつかめず遅延・トラブルが生じる <br>
            ⇩ <br>
⭐︎ 仕様を明確に/変更に適切に対応 <br>
⭐︎ できるだけ正確な見積もりをしたい <br>
⭐︎ 定量的に管理し精度を上げたい <br>

### 標準化されたマネジメント・プロセスの適用
- 長年の各業界でのグッド・プラスティスの集積
- 体系化された世界標準（PMBOK R)の利用

### 開発アプローチ
- 予測型（ウォーターフォール）
          - 原則一回のリリースで完結 <br>
(+) 計画・文書に基づいた確実なデリバリー <br>
(-) 変更への柔軟性を欠く <br>

要件定義　→ 設計　→ 構築　→ 試験　→ リリース

- 適応型（アジャイル）
          - 短期間の開発サイクルを繰り返す <br>
(+) ビジネス環境の変化に応じて柔軟な変更・デリバリー可能 <br>
(-) 文化/技術のハードルがある <br>

計画　→ 要件定義　→ 設計　→ 試験　→ リリース　→ 振り返り　（これをループする）

- ハイブリット型
          - 予測型と適応型の組み合わせ、お互いの長所を活かす

**反復型**
- 試行を繰り返し要件を明らかに <br>
**漸進型**
- 一部から段階的に作り足す

### テーラリング
- テーラーメイドされたプロジェクトマネージメント
          - 世の中に、一つとして同じプロジェクトはない <br>
→ 標準化されたプロジェクトマネジメント・プロセスを適用すれば、全てうまくいくわけではない <br>
→ そのプロジェクト（目的・規模・複雑さ・期間・組織文化・外部環境）にピッタリ合わせたプロセスとなるように、工夫を凝らさなければならない


開発アプローチの選択 →　組織のやり方への適合　→ プロジェクトの特徴への適合　→ 継続的な改善　（これをループする）
